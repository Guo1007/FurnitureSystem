## 一、系统简介

家具商城是一个基于 **Spring Boot 3 + Vue 3** 的前后端分离在线家具销售平台，品牌定位为「顾家家居」。系统支持用户浏览家具、加购下单、收藏商品、评价商品、申请退款售后、收发站内通知，并提供 AI 智能客服「小智」在线答疑。

- **前台**：家具浏览、搜索、购物车、下单、订单管理、**领券/用券**、评价、退款售后、地址收藏、AI 客服
- **后台**：数据概览、用户/商品/分类/订单管理、售后处理、评价审核、**昵称/头像审核**、通知与通知设置、优惠券及叠加规则配置、首页内容配置、操作日志审计

## 四、接口约定

### 4.1 统一响应结构

所有接口返回统一的 `Result` 结构：

```json
{
  "code": 200,
  "success": true,
  "msg": "操作成功",
  "data": {}
}
```

| 字段 | 说明 |
|------|------|
| `code` | 状态码：200 成功，401 未登录，403 无权限，500 服务异常 |
| `success` | 是否成功 |
| `msg` | 提示信息 |
| `data` | 业务数据（对象或列表） |

### 4.2 认证方式

采用 **自定义 Token 认证**（**不是 JWT**）：登录成功后服务端生成一个随机 Token，请求头携带：

```
Authorization: Bearer <token>
```

> **注意**：这里的 `Bearer` 只是沿用 HTTP 认证头的书写惯例，Token 本身是服务端生成的随机串，**没有 JWT 的三段式结构、不自带 payload、也不可解码**，请勿用 `jwt-decode` 之类工具解析。

- Token 与用户态以 **Redis Hash** 存储（`login:token:<token>` → 用户信息），天然支持服务端主动失效
- 登录/注册接口返回 token，前端存入 `localStorage`
- **多端会话按端类型互踢**：PC 端与移动端可并存，同端「后者顶前者」，被顶设备返回差异提示；改密/注销可一键清空该用户全部会话
- 游客可访问：商品浏览、评论浏览、站点内容、购物车（本地）
- 需登录：下单、收藏、评价、收货地址、通知、AI 客服
- 管理端：`/admin/**` 需管理员角色（`is_admin = 1`）

### 4.3 订单状态机

| 状态码 | 含义 |
|--------|------|
| 0 | 待支付 |
| 1 | 已支付（待发货） |
| 2 | 已发货 |
| 3 | 已完成（待评价） |
| 4 | 已取消 |
| 5 | 已评价 |
| 6 | 申请退款中 |
| 7 | 退款审核中 |
| 8 | 已退款 |

> **状态自动流转（三个定时任务，均带 Redisson 分布式锁）**
> - `OrderTimeoutScheduler`：待支付超过 `payment-timeout-minutes`（默认 1440 分钟 = 24h）自动取消并释放库存
> - `AutoReceiveScheduler`：已发货满 `order.auto-receive-days`（默认 10 天）自动确认收货 → 已完成
> - `StockAlertScheduler`：每天 10:00 / 18:00 扫描低库存并推送告警
>
> 前端在订单列表与详情会明确展示「系统将于 X 自动确认收货」，避免用户对系统行为无感知。

## 五、快速开始

### 5.1 环境依赖

- JDK 17+
- MySQL 8.x
- Redis
- RocketMQ
- 阿里云 OSS（可选，用于文件上传）

### 5.2 常用调试流程

1. 调用 `/user/register` 注册账号，或 `/user/login` 登录获取 token
2. 复制返回的 token，在 Knife4j 右上角「Authorize」中填入 `Bearer <token>`
3. 即可调试购物、下单、评价等需登录接口
4. 管理员账号（`is_admin=1`）可访问 `/admin/**` 后台接口

### 5.3 分页参数

列表接口统一使用 `current`（页码，默认1）、`size`（每页条数，默认10）分页，返回结构含 `records`、`total`、`current`、`size`。
